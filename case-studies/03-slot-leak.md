# CS-03 · คิวเต็มทั้งที่งานยกเลิกไปแล้ว — ที่นั่งค้าง 640 รายการ

> **สรุปสั้น:** สถานะที่ไม่มีใครทดสอบคือสถานะที่พัง
> และการแก้โค้ดให้อนาคตถูก ไม่ได้ทำให้ข้อมูลที่พังไปแล้วหายไปเอง

| | |
|---|---|
| **ระบบ** | แพลตฟอร์มจองคิวบริการ (Firebase / Cloud Functions) |
| **บทบาทของผม** | หาสาเหตุ, เสนอทางแก้, เขียน script แก้ข้อมูลย้อนหลัง, ทดสอบ |
| **เทคนิคที่ใช้** | state-transition testing, data-integrity check, idempotent remediation |

## อาการที่ผู้ใช้เจอ

ลูกค้าจองคิวไม่ได้ ระบบแจ้งว่าช่วงเวลานั้นถูกจองแล้ว **ทั้งที่งานเดิมในช่วงเวลานั้นถูกยกเลิกไปแล้ว**

## สาเหตุราก

ตอนสร้างงาน ระบบจะ "จอง" ที่ในตารางเวลาเอาไว้ แต่ตอนงานเปลี่ยนสถานะเป็น **ยกเลิก** หรือ **ถูกปฏิเสธ** — **ไม่มีใครคืนที่นั่งนั้นกลับเข้าระบบ**

```
สร้างงาน      ──► จองที่ในตาราง ✅
ยกเลิกงาน     ──► สถานะงานเปลี่ยน ✅   แต่ที่ในตารางยังค้างอยู่ ❌
จองใหม่ช่วงเดิม ──► ถูกปฏิเสธเพราะ "เต็ม" ทั้งที่ว่าง
```

เป็นช่องว่างแบบคลาสสิกของ state-transition: ทุกคนทดสอบเส้นทาง **สร้าง → เสร็จงาน** แต่เส้นทาง **สร้าง → ยกเลิก → จองใหม่** ไม่มีใครไล่

## การแก้ — สองส่วน ไม่ใช่ส่วนเดียว

**1. แก้ให้อนาคตถูก** — ทำ trigger ที่ทำงานเมื่อสถานะงานเปลี่ยนเป็นยกเลิก/ถูกปฏิเสธ แล้วคืนที่นั่งอัตโนมัติ

**2. แก้ข้อมูลที่พังไปแล้ว** — เขียน script ไล่หางานที่ยกเลิกแล้วแต่ยังกินที่อยู่ แล้วคืนให้ครบ ผลลัพธ์: **ปลดที่นั่งที่ค้างได้ 640 รายการ**

หลักที่ยึดตอนเขียน script แก้ข้อมูล production:

- **dry-run เป็นค่าเริ่มต้น** ต้องพิมพ์ `--apply` เท่านั้นถึงจะเขียนจริง — คนที่รันผิดพลาดจะได้แค่รายงาน ไม่ใช่ข้อมูลที่เปลี่ยนไปแล้ว
- **รันซ้ำได้ (idempotent)** มี flag กำกับว่ารายการไหนคืนที่ไปแล้ว รันซ้ำจะข้ามให้ ไม่ทำซ้ำซ้อน
- **ใช้ logic เดียวกับ trigger** ไม่เขียนสูตรคืนที่ขึ้นมาใหม่อีกชุด ซึ่งจะกลายเป็นแหล่งบั๊กที่สอง

## บทเรียนที่เอาไปใช้ต่อ

- **ทดสอบ state transition ให้ครบทุกเส้น ไม่ใช่แค่เส้น happy path** โดยเฉพาะเส้นย้อนกลับ (ยกเลิก / ปฏิเสธ / คืนของ) ซึ่งมักเป็นเส้นที่คนเขียนโค้ดลืม
- **บั๊กที่ทำข้อมูลเพี้ยนสะสม ต้องวางแผนสองชั้นเสมอ** — หยุดเลือดออก + ตามเก็บของที่พังไปแล้ว ถ้าทำแค่ชั้นแรก ผู้ใช้จะยังเจอปัญหาเดิมต่อไป
- **script ที่แตะข้อมูล production ต้อง dry-run เป็นดีฟอลต์** ความปลอดภัยควรเป็นค่าเริ่มต้น ไม่ใช่สิ่งที่ต้องจำว่าต้องใส่
