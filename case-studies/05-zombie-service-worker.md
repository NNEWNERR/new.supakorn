# CS-05 · deploy แล้วบางเครื่องเห็นหน้าเก่า — service worker ที่ตายไม่ลง

> **สรุปสั้น:** "เครื่องผมเห็นปกตินะ" คือหลักฐาน ไม่ใช่ข้อแก้ตัว
> ถ้า incognito ปกติแต่หน้าต่างธรรมดาเพี้ยน แปลว่าปัญหาอยู่ในเครื่องผู้ใช้ ไม่ใช่ที่ server

| | |
|---|---|
| **ระบบ** | เว็บแอปจัดการงานร้าน (Angular + Firebase Hosting) |
| **บทบาทของผม** | รับเรื่องจากผู้ใช้, ไล่หาสาเหตุ, ออกแบบวิธีแก้, ตรวจสอบหลัง deploy |
| **เทคนิคที่ใช้** | แยกตัวแปรทีละตัว, ตรวจที่ HTTP header ไม่ใช่ที่ตา |

## อาการ

หลัง deploy เวอร์ชันใหม่ ผู้ใช้**บางคน**เห็นหน้าเว็บเพี้ยน CSS เป็นของเวอร์ชันเก่า ขณะที่ผู้ใช้อีกกลุ่มเห็นปกติดี

## วิธีแยกว่าปัญหาอยู่ที่ไหน

1. **ตรวจว่า server ส่งของถูกไหม** — ยิงตรงไปที่ไฟล์ CSS, ฟอนต์ และ bundle บน production ได้ **200 และเป็นเวอร์ชันใหม่ครบทุกไฟล์** → server ไม่ผิด
2. **เปิดด้วยหน้าต่าง incognito** — **ปกติทุกอย่าง** → ไม่ใช่ปัญหา build ไม่ใช่ปัญหา deploy
3. เหลือความเป็นไปได้เดียว: **มีอะไรบางอย่างค้างอยู่ในเบราว์เซอร์ของผู้ใช้กลุ่มนั้น**

ข้อ 2 คือจุดตัดสิน incognito ไม่มีของเก่าค้าง ถ้า incognito ปกติแต่หน้าต่างธรรมดาเพี้ยน คำตอบอยู่ในฝั่ง client เสมอ

## สาเหตุราก

แอปเวอร์ชันก่อนหน้าเคยเป็น PWA จึงติดตั้ง **service worker** ไว้ในเบราว์เซอร์ของคนที่เคยเข้า — มันทำหน้าที่ส่งไฟล์ที่ cache ไว้แทนการโหลดจาก server

พอเขียนแอปใหม่โดยไม่ใช้ PWA แล้ว service worker ตัวเก่า **ยังทำงานอยู่ในเครื่องผู้ใช้** และยังส่งของเก่าให้ต่อไป

ส่วนที่ทำให้มันไม่หายเองคือ: เบราว์เซอร์จะเช็คอัปเดต service worker ด้วยการโหลดไฟล์สคริปต์ของมันซ้ำ แต่แอปใหม่ตั้ง SPA rewrite ให้ทุก path ที่ไม่รู้จักตอบด้วยหน้า HTML หลัก — คำขอไฟล์ service worker จึงได้ **HTML กลับไปแทน JavaScript** เบราว์เซอร์จึงอัปเดตมันไม่ได้ และตัวเก่าก็ค้างอยู่อย่างนั้น **แม้กด hard refresh**

## การแก้

วางไฟล์ JavaScript จริงทับตำแหน่งที่ service worker ตัวเก่าจะมาเรียก (ครอบทุกชื่อไฟล์ยอดนิยมที่เฟรมเวิร์กต่างๆ ใช้) โดยไฟล์นั้นทำแค่สามอย่าง: **ล้าง cache → ถอนการติดตั้งตัวเอง → สั่ง reload**

พร้อมตั้ง `Cache-Control: no-cache` กับไฟล์กลุ่มนี้ เพื่อไม่ให้มันถูก cache ซ้ำเข้าไปอีก

ผลคือเบราว์เซอร์ที่มีของเก่าค้างจะล้างตัวเองทิ้งในการเข้าครั้งถัดไป ส่วนเบราว์เซอร์ที่ไม่เคยติดตั้งอะไรไว้ไม่ได้รับผลกระทบ

## การยืนยัน

ไม่ตรวจด้วยการเปิดดูแล้วบอกว่า "หายแล้ว" แต่ตรวจที่ header ตรงๆ:

```
ต้องได้  content-type: text/javascript   ← ไฟล์ JS จริง
ห้ามได้  content-type: text/html         ← แปลว่า rewrite ยังกินอยู่ ยังไม่หาย
```

เพราะ "เปิดแล้วดูปกติ" อาจเป็นเพราะ cache ของเครื่องที่ใช้ตรวจเองก็ได้

## บทเรียนที่เอาไปใช้ต่อ

- **"เครื่องผมปกติ" เป็นข้อมูลที่มีค่า** ไม่ใช่คำที่ควรรำคาญ — ความต่างระหว่างเครื่องที่เห็นบั๊กกับเครื่องที่ไม่เห็น คือเส้นทางที่สั้นที่สุดไปหาสาเหตุ
- **incognito คือเครื่องมือแยกตัวแปรที่เร็วที่สุดของงาน front-end** ใช้เวลา 5 วินาที แต่ตัดความเป็นไปได้ออกไปได้ครึ่งหนึ่ง
- **ยืนยันด้วยข้อมูลที่เครื่องมือวัดได้ ไม่ใช่ด้วยสายตา** โดยเฉพาะบั๊กเรื่อง cache ที่การ "เปิดดูแล้วโอเค" เชื่อถือไม่ได้เลย
- **การเลิกใช้เทคโนโลยีบางอย่าง ไม่ได้จบแค่ลบโค้ดออก** ของที่เคยติดตั้งไว้ในเครื่องผู้ใช้ยังอยู่ และเป็นความรับผิดชอบของเราที่ต้องตามไปเก็บ
